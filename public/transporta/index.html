01 / La traducción

Mismo programa. Otro lenguaje.

Baja despacio: cada línea de Java se reescribe en su equivalente ABAP. Así se lee el resto de la guía.

  1. variable → declaración en línea con DATA( )
  2. repositorio JPA → ABAP SQL
  3. for-each → LOOP AT
  4. getter → componente con guion
  5. método estático → operador =>
  6. llave de cierre → ENDIF
  7. llave de cierre → ENDLOOP
  8. JUnit → ABAP Unit

02 / Por qué ABAP

Miles de empresas tienen que migrar a S/4HANA. Faltan manos.

  • 2027

    El mantenimiento estándar de SAP ECC termina a finales de 2027. Las empresas que siguen en ECC están migrando a S/4HANA, y cada migración necesita gente que programe en ABAP.

  • ABAP Cloud

    El ABAP que se pide hoy es orientado a objetos, se escribe en Eclipse, tiene tests unitarios y se versiona con Git. Se parece más a tu Java de lo que imaginas.

  • Tu base

    Diseñar clases, escribir tests y pensar en capas ya lo sabes. La sintaxis se aprende en semanas.

  PUBLIC SECTION.

La tabla que más vas a consultar al principio. La regla de oro: nunca uses coma flotante para dinero, ni en Java ni en ABAP.

05 / Errores típicos

Los dumps que vas a ver y cómo arreglarlos

Ocho problemas que le pasan a todo el que llega de Java, con su explicación en Java y la solución lista para copiar.

8 errores

Qué pasa. Una expresión de tabla como lt_pedidos[ id = lv_id ] lanza un dump si la línea no existe.

En Java sería un get() que lanza una excepción en vez de devolver null.

solucion.abap
" Opción 1: valor por defecto si no existe
DATA(ls_pedido) = VALUE #( lt_pedidos[ id = lv_id ] OPTIONAL ).

" Opción 2: comprobar antes de leer
IF line_exists( lt_pedidos[ id = lv_id ] ).
  ls_pedido = lt_pedidos[ id = lv_id ].
ENDIF.

Qué pasa. Llamas a un método sobre una referencia que nunca se instanció.

En Java sería exactamente un NullPointerException. La solución es la misma: comprobar antes o instanciar a tiempo.

solucion.abap
IF lo_servicio IS NOT BOUND.
  lo_servicio = NEW zcl_servicio( ).
ENDIF.

lo_servicio->procesar( ).

Qué pasa. Una consulta por cada línea del bucle. Con mil pedidos, mil viajes a la base de datos.

En Java sería el problema N+1 de Hibernate con las relaciones perezosas. Se arregla igual: una sola consulta con JOIN.

solucion.abap
" Una sola consulta en lugar de una por pedido
SELECT p~id, p~importe, c~nombre
  FROM zpedidos AS p
  INNER JOIN zclientes AS c ON c~id = p~cliente_id
  INTO TABLE @DATA(lt_resultado).

Qué pasa. Si la tabla de FOR ALL ENTRIES está vacía, el WHERE se ignora y el SELECT lee la tabla entera.

En Java sería un WHERE id IN (...) con la lista vacía que, en vez de no devolver nada, lo devuelve todo. Es el error más caro de esta lista.

solucion.abap
IF lt_clientes IS NOT INITIAL.
  SELECT id, importe
    FROM zpedidos
    FOR ALL ENTRIES IN @lt_clientes
    WHERE cliente_id = @lt_clientes-id
    INTO TABLE @DATA(lt_pedidos).
ENDIF.

Qué pasa. Campos como el número de cliente o de material se guardan con ceros a la izquierda. Si buscas "42", no encuentras nada.

En Java sería comparar "42" con "0000000042". La conversión ALPHA pone y quita esos ceros.

solucion.abap
DATA lv_cliente TYPE kunnr.

" 42 -> 0000000042
CALL FUNCTION 'CONVERSION_EXIT_ALPHA_INPUT'
  EXPORTING input  = lv_entrada
  IMPORTING output = lv_cliente.

" 0000000042 -> 42, para mostrarlo
CALL FUNCTION 'CONVERSION_EXIT_ALPHA_OUTPUT'
  EXPORTING input  = lv_cliente
  IMPORTING output = lv_entrada.

Qué pasa. El tipo f es coma flotante binaria: 0,1 + 0,2 no da exactamente 0,3 y los redondeos se acumulan.

En Java sería usar double para importes en lugar de BigDecimal. En ABAP, el equivalente de BigDecimal es el tipo p.

solucion.abap
DATA lv_importe TYPE p LENGTH 15 DECIMALS 2.

lv_importe = '19.99' * 3.   " 59.97, sin sorpresas

Qué pasa. SELECT SINGLE y READ TABLE no lanzan excepción si no encuentran nada: dejan un código en SY-SUBRC. Si no lo miras, sigues trabajando con datos vacíos.

En Java sería no comprobar si un Optional está vacío antes de usarlo.

solucion.abap
SELECT SINGLE nombre
  FROM zclientes
  WHERE id = @lv_id
  INTO @DATA(lv_nombre).

IF sy-subrc <> 0.
  RAISE EXCEPTION NEW zcx_cliente_no_existe( ).
ENDIF.

Qué pasa. En ABAP guardar no es activar. Mientras no actives, el sistema sigue ejecutando la versión anterior. Y si el objeto está en la orden de transporte de otra persona, no podrás cambiarlo.

En Java sería editar el código y olvidarte de recompilar.

  1. 01

    Activa con Ctrl + F3. Si el objeto depende de otros que también cambiaste, actívalos juntos.

  2. 02

    Mira en SE09 en qué orden de transporte está el objeto y quién la tiene.

  3. 03

    Si hay un bloqueo que ya no debería existir, revísalo en SM12 junto con quien administre el sistema.

06 / Snippets

Código que vas a copiar mil veces

Ocho fragmentos de ABAP moderno, cada uno con su equivalente en Java en la primera línea.

El primer programa que vas a escribir en Eclipse. Se ejecuta con F9 y escribe en la consola de ADT.

zcl_hola.clas.abap
" Java: public static void main(String[] args)
CLASS zcl_hola DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    INTERFACES if_oo_adt_classrun.
ENDCLASS.

CLASS zcl_hola IMPLEMENTATION.
  METHOD if_oo_adt_classrun~main.
    out->write( |Hola desde ABAP, { cl_abap_context_info=>get_user_technical_name( ) }| ).
  ENDMETHOD.
ENDCLASS.

Crear una tabla nueva con las líneas que cumplen una condición, sin bucle ni APPEND.

filtrar.abap
" Java: pedidos.stream().filter(p -> p.getImporte() > 1000).toList()
DATA(lt_grandes) = VALUE tt_pedidos(
  FOR ls_p IN lt_pedidos WHERE ( importe > 1000 )
  ( ls_p ) ).

Acumular un valor recorriendo la tabla. REDUCE es el reduce de los streams.

sumar.abap
" Java: pedidos.stream().map(Pedido::getImporte).reduce(BigDecimal.ZERO, BigDecimal::add)
DATA(lv_total) = REDUCE decfloat34(
  INIT suma = CONV decfloat34( 0 )
  FOR ls_p IN lt_pedidos
  NEXT suma = suma + ls_p-importe ).

Recorrer la tabla por grupos y calcular un total por cliente.

agrupar.abap
" Java: Collectors.groupingBy(Pedido::getCliente)
LOOP AT lt_pedidos INTO DATA(ls_p)
     GROUP BY ls_p-cliente_id INTO DATA(lv_cliente).

  DATA(lv_suma) = REDUCE decfloat34(
    INIT s = CONV decfloat34( 0 )
    FOR ls_m IN GROUP lv_cliente
    NEXT s = s + ls_m-importe ).

  out->write( |Cliente { lv_cliente }: { lv_suma }| ).
ENDLOOP.

Pasar los datos de una estructura a otra por nombre de campo, renombrando o excluyendo los que haga falta.

mapear.abap
" Java: MapStruct o BeanUtils.copyProperties
DATA(ls_dto) = CORRESPONDING zs_pedido_dto( ls_pedido
  MAPPING cliente = cliente_id
  EXCEPT  importe_interno ).

    11 / Cómo viaja tu código

    No hay git push. Hay órdenes de transporte.

    En Java haces push y el pipeline despliega. En SAP el código viaja dentro de órdenes de transporte por un paisaje de sistemas. Es lo primero que choca.

    1. DEV

      Desarrollo

      Programas y activas. Cada cambio queda registrado en una orden de transporte que ves en SE09. Cuando está lista, la liberas.

    2. QAS

      Calidad

      La orden se importa en un sistema de pruebas con datos parecidos a los reales. Aquí se valida antes de seguir.

    3. PRD

      Producción

      Aquí no se programa. Solo llega lo que ha pasado por DEV y QAS, en el mismo orden en que se liberó.

    14 / Preguntas

    Lo que pregunta todo programador Java

    No. Es el lenguaje de SAP S/4HANA y de ABAP Cloud en SAP BTP, y las migraciones desde ECC mantienen la demanda de gente que lo programe.

    No. SAP ofrece una cuenta de prueba gratuita de SAP BTP con entorno ABAP, y también ABAP Platform Trial para instalar un sistema en local.

    ADT para programar: es lo moderno y lo único disponible en ABAP Cloud. SAP GUI lo seguirás usando en sistemas clásicos y para muchas transacciones.

    No como en Java. Cada variable nace con su valor inicial (cero, espacios o una fecha vacía) y se comprueba con IS INITIAL. Las referencias sí pueden no apuntar a nada, y eso se comprueba con IS BOUND.

    No como los de Java. Para parámetros flexibles se usan tipos genéricos como TYPE any o TYPE ANY TABLE, y referencias a datos con REF TO data.

    Las palabras clave y los nombres no; los literales de texto sí. Muchos equipos escriben las palabras clave en mayúsculas, y el formateador de ADT (Mayús + F1) lo deja todo uniforme.

    En ADT, con puntos de interrupción como en cualquier IDE. En SAP GUI, escribiendo /h en la barra de comandos antes de ejecutar.

    Sí. Los objetos que ya no tienen referencias se liberan solos, igual que en Java.
